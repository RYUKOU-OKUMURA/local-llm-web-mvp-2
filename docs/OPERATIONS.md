# 運用・障害対応・安全上の境界

## 1. ファイルの場所

実機の固定ルートは`$HOME/Library/Application Support/local-llm-web`です。以下のパスは実機で生成され、配布ZIPには秘密値を入れていません。

| パス | 用途 |
|---|---|
| `venv/` | 専用Python 3.11とOpen WebUI本体 |
| `data/` | SQLite、添付、Chroma、トークナイザー等 |
| `config/state.json` | 採用版・ポート・モデル・導入フェーズ・経路追加記録 |
| `config/webui.env` | WebUI設定とWEBUI_SECRET_KEY |
| `config/ollama.env` | Ollamaのloopback・クラウド停止・負荷制限 |
| `config/requirements.in` / `requirements.lock` | 固定版とMacで解決した依存関係・ハッシュ |
| `config/config-key-map.json` | インストールされたソースから確認した設定キー |
| `scripts/` | 自動起動用のラッパー・このパッケージのコピー |
| `logs/` | サービス別stdout/stderr |
| `records/` | バージョン、モデル、設定・Serve前後の私的記録 |
| `backups/` | 停止中スナップショット |
| `restore-tests/` | 独立した復元試験コピー |

ルート/設定/記録等は所有者専用、秘密ファイルは600、スクリプトは700で作ります。アプリが生成するファイルもumask 077下で作成されます。所有者専用でない設定やsymlinkを検出したら停止します。**envはシェルでsourceしない独自のKEY="JSON文字列"形式**です。シェル展開による誤実行を防ぐためPythonで解釈します。

## 2. 既存環境を守る仕組み

プログラムが管理するジョブは`local.llmweb.ollama`と`local.llmweb.webui`だけです。plistのラベルだけでなくProgramArguments・作業場所等が完全一致するか確認します。待受PIDもLaunchAgentのPIDと照合し、他のプロセスを名前でまとめて停止しません。

新規Serve経路は追加前後を比較し、専用ポート以外が変わったら新規WebUIを停止して調査を要求します。既存全体のスナップショットを機械的に復元する処理はありません。OpenClawなどが同時に設定を変える可能性があるからです。

`unpublish`は「このパッケージが追加した記録」と「現在の経路の完全一致」の両方を求めます。他人のHandler、異なるProxy、Funnel、別の前景セッションがある場合は停止します。**`tailscale serve reset`は使わないでください。**

初期設定では、新規HTTPSポートの空きだけでなく、別の既存Serve HandlerがWebUI待受ポートへ既に転送していないことも確認します。SSH転送や別製品のプロキシまで自動列挙する機能ではないので、手動で用意した転送がある場合は本人が確認してください。

## 3. 起動・停止

```bash
bash ./llmweb start all
bash ./llmweb stop webui
bash ./llmweb start webui
bash ./llmweb doctor
```

LaunchAgentはログインセッション単位です。RunAtLoadと異常終了時再起動を設定し、短時間の再試行が続かないようThrottleIntervalを10秒にしています。繰り返し失敗していたら`stop`でジョブを外し、原因を確認します。単にPIDへシグナルを送ってもKeepAliveによって再起動し得るため、保守では専用CLIを使います。

WebUIはOllamaの準備を最大60秒待ちます。Ollamaのサーバー起動を待つだけで、モデルのロード完了まで待つ処理ではありません。

`stop`は当該セッションのジョブを外す操作であり、plistを削除しません。次回ログインで再開します。**自動起動も停止したい場合**は、`stop all`を成功させた後に、`~/Library/LaunchAgents`内の上記2ファイルだけを別の保管場所へ移動します。Ollama.appのログイン項目や他人のLaunchAgentをまとめて消さないでください。

FileVault解除・OSログインが必要な再起動後は、本人がそれを行ってから復帰を確認します。OS保護の無効化、自動ログインの有効化、スリープ設定の無断変更はありません。

## 4. 設定の変更

表示言語・会話名などは標準UIで変更できます。接続先・新規登録・外部ツール・実行機能などの安全設定は変更しない運用です。Open WebUIの永続設定が環境変数に優先し得るため、envだけの変更で反映完了としません。[S-02]

安全設定を再適用する場合は、先に`unpublish`してから`secure`、内容を確認して`publish`の順です。GUIでの安全設定変更を常時監視するサービスは作っていません。管理者が後から外部APIを登録する行為まで、このパッケージがOS権限で禁止するものではありません。

HTTPS運用の自動起動では、DBの有無と`user`テーブル内の管理者1名を**読み取り専用の件数確認**で検査します。DB消失・管理者不在・未知のスキーマなら起動を拒否し、初期管理者画面を誤って再公開しないようにします。設定やアカウントをSQLで更新する処理はありません。仕様が変わった場合にガードを削るのではなく、上流ソースを確認してください。[S-07]

## 5. バックアップ

```bash
bash ./llmweb backup
```

専用WebUIジョブを外し、待受停止とプロセスロックを確認してから`data/config/scripts/records`をコピーします。SQLite quick_check、全ファイルのSHA-256一覧を保存します。途中失敗は`.incomplete`として残り、完成したバックアップと区別されます。もともと稼働していたWebUIは工程の最後に再開を試みます。再開失敗はエラーとして扱います。

venv本体、Ollamaのモデル重み、ログはコピーしません。アプリは保存された版と依存ロックから再構成、モデルはタグ・ダイジェストの記録を利用します。ただし上流配布物が将来も取得可能である保証はないため、長期の完全オフライン復旧を求めるなら配布物・モデルの別保管が必要です。これは初期パッケージの自動化範囲外です。

**秘密鍵・パスワードハッシュ・会話・添付を含む未暗号化バックアップ**です。所有者専用の保存でも、本体故障・盗難・OSユーザー侵害への十分な対策ではありません。本人の管理下にある暗号化した別媒体へ保管し、保管状況を記録してください。クラウドへ勝手にアップロードしません。

更新前・初期導入の受け入れ完了時に実施します。日常の週1回は手動の運用案です。スケジュール実行やローテーションの自動サービスは未実装です。

## 6. 隔離した復元試験

実行例の日時は、実際の`backup`出力のフォルダへ置換します。

```bash
bash ./llmweb restore-test \
  "$HOME/Library/Application Support/local-llm-web/backups/<実際のバックアップ名>"
```

本番WebUIを停止し、ハッシュとSQLiteの整合性、アプリ版の一致を確認します。`restore-tests`内の**新規コピー**を`127.0.0.1:3010`で起動します（使用中なら近い空き番号へ自動割当）。Serveに公開せず、Mac miniのブラウザだけで確認します。過去の会話・添付の参照・設定を確認し、Ctrl+Cで試験を終了します。本番は元のデータのまま再開を試みます。

隔離コピーでのみ`ENABLE_PERSISTENT_CONFIG=false`を使い、保存された公開URLやCookie設定に依存せずローカル試験を行います。本番ではtrueを維持します。**バックアップ全設定がそのまま運用可能なことをこの試験だけで保証しません。** 実機の採用設定との照合も必要です。

隔離コピーは終了後も残ります。秘密データを含むため適切に管理してください。自動的な本番への上書き復元コマンドはありません。

## 7. 更新と本番ロールバック（手順のみ）

0.1.0では自動アップグレードを実装しません。導入済みの`install`は何も上書きせず終了します。

更新は、遠隔経路を閉じる→整合バックアップ→専用WebUI停止→候補の正確な版を新venvで検証→設定キー/API/DB移行を確認→受け入れ試験、の順です。旧版へ戻す際は**旧アプリと対応するバックアップデータを一組**で戻します。DB移行後にアプリだけダウングレードしないでください。[S-08]

ロールバック担当者は、現行データを別途保全し、対象ジョブ停止・専用ポート非公開を確認してからコピーを配置します。元データは削除しません。復旧確認後にだけ遠隔経路を再追加します。FileVaultやOS認証などを迂回して復旧しません。

## 8. よくある停止理由

| 表示・症状 | 対応 |
|---|---|
| 11434が使用中 | 既存Ollamaの起動元を調査。利用者確認なしに停止しない |
| 3001/9443が使用中 | installが近い空きポートへ自動割当（明示指定も可）。既存443は動かさない |
| 安全設定キーが見つからない | `records/package-inspection.json`とインストール版ソースを確認。必須チェックを消さない |
| 保存設定が一致しない | 管理APIの形式/永続化値を確認。DATA_DIRを削除しない |
| モデルが未取得 | 設定タグを確認し`pull-models`。外部APIへ切り替えない |
| WebUI起動が失敗 | `logs/webui.stderr.log`とstdout、Python依存、Ollama状態、オフライン用キャッシュを確認 |
| 文書だけ失敗 | 埋め込みモデル・拡張子・容量・標準抽出器を確認。外部OCRを有効化しない |
| publish途中失敗 | 新規WebUI停止・経路追加記録を確認。必要なら`unpublish`。Serve全体をresetしない |
| HTTPS接続不可 | Tailscale接続、ACL、既存Serve、証明書を確認。TLS検証を無効にしない |
| OpenClaw側にも影響 | 新規WebUI/Ollamaを専用CLIで停止し、資源競合とServe変更記録を比較 |

## 9. 残る安全上の境界

「ローカル」とは、推論・文書抽出/埋め込み・主保存先をMac miniに置く設計です。初期取得・Tailscale・更新の通信は発生します。OFFLINE_MODE/HF_HUB_OFFLINEは全通信を遮断する機構ではありません。[S-02][S-09]

専用venvは依存分離であり、macOS Sandboxではありません。Open WebUI/Ollamaは実行ユーザーの権限を持ちます。モデル・文書は無条件に信頼せず、外部Tools/Functions、MCP、コード実行、クラウドAPIを追加しません。上流の脆弱性やOSユーザー侵害まで防ぐ保証はありません。[S-10]

ブラウザにはCookie・キャッシュ・ダウンロードが残り得ます。また同じホスト名の443/9443ではCookieをポートで完全分離できません。OpenClawとの同時利用をAT-19で確認します。[S-11]

ログ・設定スナップショットを他人へ渡す前には、本文・キー・内部URLを人が確認して秘匿します。ログ自動ローテーションは未実装です。まず週1回サイズを確認し、サービス停止中に必要分を保管してください。ディスクを空けるためにdata/modelsを自動削除しません。

出典の対応は[SOURCES.md](SOURCES.md)を参照してください。
