# 個人用ローカルLLM Web環境 — 要件定義

## 1. この文書の位置づけ

Mac miniで動くローカルLLMを、MacBookなどのブラウザから日常的に利用するための要件を定める。**OllamaとOpen WebUIの両方をmacOS上で直接実行する構成は、ユーザー承認済みの前提**であり、Docker版や自作UIへ戻して比較し直すことはしない。

本書は「何を満たしたら導入完了か」を扱う。実装用の設定値は[技術スタック](02_technology-stack.md)、配置・通信・運用手順は[アーキテクチャ](03_architecture.md)を参照する。

`local-llm-web`は保存先やサービス名を統一するための内部識別子であり、商品名ではない。本書作成時点で、Mac miniへのインストール、既存設定の変更、性能測定は実施していない。

## 2. 目的と完了イメージ

**目的：MacBookでブラウザを開くと、Mac mini上のOllamaのモデルと会話でき、履歴と添付文書を同じ場所で使い続けられる状態をつくる。**

初期導入が完了した状態では、普段の利用のためにMacBookでOllama、Python、Dockerを起動する必要がない。自宅と職場など別ネットワークからも、既存Tailscale経由で同じOpen WebUIにアクセスする。

本プロジェクトは、既存製品の導入・設定・運用整備である。Webアプリの新規開発や、顧客向け製品化のための基盤開発ではない。

## 3. 確定した構成と変更禁止事項

| 項目 | 採用方針 |
|---|---|
| サーバー | 既存のMac mini 1台 |
| 推論エンジン | OllamaをmacOSでネイティブ実行 |
| Web画面 | Open WebUIの配布済みPythonパッケージを利用 |
| Python実行環境 | 専用Python 3.11仮想環境をuvで管理 |
| 推論API | `http://127.0.0.1:11434`。Mac内部のみ |
| WebUI待受 | `http://127.0.0.1:3001`。Mac内部のみ。使用中の場合は導入時に近い空きポートを自動割当 |
| リモート入口 | 既存Tailscale ServeにHTTPS 9443番を追加する。未使用であることが前提 |
| 正規URL | `https://<MAC_MINI_FQDN>:9443`。実際のFQDNはTailscaleで確認 |
| 会話データ | Mac mini上の専用DATA_DIR。Open WebUI標準SQLiteを利用 |
| 文書検索データ | Open WebUI標準のローカルChroma。外部DBサーバーは追加しない |
| 起動管理 | ユーザー単位のlaunchd LaunchAgent。Ollamaの多重起動を禁止 |
| 利用者 | BOSS本人1名。Open WebUI独自のログインを有効にする |
| ネットワーク | 既存Tailnetを流用。Funnel・ルーターのポート転送は使わない |
| 既存OpenClaw | Gateway、認証、Docker Sandbox、443番の既存Serve設定を維持 |

OllamaのmacOS対応、Open WebUIのPython導入、Ollama接続、Tailscale Serveの方式には公式資料がある。[OL-01][OW-01][OW-02][TS-01]

既存OpenClawについては、9月6日の設定レポートに「GatewayはmacOS上の`127.0.0.1:18789`、DockerはSandbox用途、Tailscale Serveで公開」とある。ただし、これは過去の確認結果であって現在の稼働状態の保証ではない。導入前に読み取り専用で再確認する。[U-02]

### 変更してはいけないもの

- OpenClawのGateway設定、トークン、Sandbox、workspace、既存の443番経路。
- 既存Dockerコンテナ、Docker全体、ほかのプロジェクトのPython環境。
- Mac miniのホスト名、既存Tailnetへの所属、既存利用者のアクセス権。
- FileVault、OSのセキュリティ機構、自動ログイン設定。利便性のために勝手に弱めない。

3001番または9443番に競合があれば、既存プロセスを停止・削除せず、新規側の未使用ポートを自動で一時割当する。変更は3文書と実機の構成記録へ反映し、既存側を変えないという原則を守る。

## 4. 利用者・端末・運用条件

| 区分 | 要件 |
|---|---|
| 主利用端末 | MacBookのブラウザ。Mac miniのブラウザも同じWebUIを利用 |
| 追加端末 | Pixel・iPadのブラウザ。Tailscaleに参加済みの端末だけを対象 |
| 主利用ブラウザ | MacBookのChrome。Safariは補助確認対象 |
| 言語 | UIは日本語設定を利用し、会話も日本語で利用可能 |
| 同時利用 | 1人。複数端末で履歴を開けるが、生成処理は原則1件ずつ |
| Mac miniの状態 | 電源ON、ネット接続あり、Tailscale稼働、必要サービス稼働 |
| ログイン条件 | 運用用macOSユーザーのログイン後にサービスが自動起動する |
| 電源断後 | FileVault解除やOSログインを必要とする場合がある。無人完全復旧は初期要件外 |

MacBookがインターネットへ接続できない状態で、外出先からMac miniへアクセスする機能は含めない。Mac mini自身でのローカル利用と、ネットワーク経由の遠隔利用を区別する。

## 5. 対象範囲

### 5.1 初期リリースに含めるもの

日本語チャット、ストリーミング返信、モデル選択、会話履歴、テキスト文書の添付・質問、同一アカウントによる端末間の履歴利用、認証、ローカル保存、ログイン後自動起動、バックアップ・復元手順、既存OpenClawとの共存確認を含める。

ファイル添付は「利用者が選んだ文書」を扱う機能であり、Mac miniの全ファイルを自動収集する機能ではない。

### 5.2 初期リリースに含めないもの

自作UI、Open WebUIのフォーク、独自バックエンド、商用販売、複数社員への配布、SSO、課金、外部LLM API、Web検索、MCP、エージェント、サブエージェント、Tools・Functionsの追加、コード実行、音声入出力、画像生成、常時フォルダ監視、OCR、Google Drive・Dropbox同期、OpenClawとのデータ共有、外部ベクトルDB、クラスタ化は対象外。

通常のコードの説明やコードブロックの表示は禁止しない。「コード実行をしない」とは、そのコードを自動実行する環境を提供しないことを意味する。

顧客・患者の実データを扱う業務運用も初期対象外とする。本構成だけを理由に、医療・個人情報保護上の適合性が確認できたとは扱わない。

## 6. 機能要件

### FR-01：認証付きのブラウザアクセス

Tailscale接続済みのMacBookから正規HTTPS URLへアクセスし、Open WebUIの本人用アカウントでログインできること。ネットワークの認証とWebUIの認証を分け、OpenClawのトークンは転用しない。

初回管理者を作成した後は新規登録を無効化する。初期管理者が未作成の画面をTailnet全体へ開放しない。具体的な初期設定手順はアーキテクチャ第7節に定める。

**完了条件：AT-03、AT-08、AT-10、AT-11に合格する。**

### FR-02：日本語の基本チャット

新しい会話を作成し、日本語の質問にローカルモデルから回答を得られること。標準UIのストリーミング表示、生成停止、回答コピーを利用する。再生成・入力編集は採用バージョンの標準機能の範囲で利用し、独自実装はしない。

モデル読み込み中や処理中の状態を確認できること。停止操作後に表示だけが止まり、生成処理が長時間残り続けないかを実機で確認する。Ollamaサーバーが稼働し続けることや、モデルがメモリにキャッシュされること自体は停止失敗とみなさない。

**完了条件：AT-04、AT-05に合格する。**

### FR-03：ローカルモデルの選択

Ollamaに導入済みのチャットモデルをOpen WebUIで選択できること。モデル名、タグ、ダイジェスト、量子化、用途を構成記録に残す。クラウドモデルを選択候補に入れない。

モデル切替試験では軽量なチャットモデル2種類を順番に試す。常時2種類をメモリへ載せる必要はない。実用モデルはMac miniのチップ・メモリ・負荷を測定したうえで決める。特定の大規模モデルの速度は保証しない。

モデルの取得・更新・削除は保守作業とし、日常の会話から勝手にダウンロードを始める運用にはしない。

**完了条件：AT-02、AT-06に合格する。**

### FR-04：会話履歴の保存と継続

会話を閉じて再度開き、過去のやり取りを確認・継続できること。MacBookとMac miniから同じアカウントでアクセスした際、同じ履歴を参照できること。

同一会話を複数端末で同時編集する共同編集機能は要求しない。履歴の反映にページ再読み込みが必要でもよい。ブラウザの一時保存だけに依存せず、DATA_DIRに永続化する。

**完了条件：AT-07、AT-13に合格する。**

### FR-05：文書添付と文書に基づく回答

初期対象はUTF-8の`.txt`、`.md`、文字情報を持つ`.pdf`とする。PDFの図表理解、スキャンPDF、手書き、パスワード保護PDF、複雑な段組みの再現は対象外。

最初の運用上限は1ファイル10MiB、1会話5ファイルとする。これは製品の最大性能ではなく、本プロジェクトの保守的な初期値である。採用バージョンに対応する設定項目で制限し、件数を厳密に設定できない場合は運用制限であることを明記する。

添付ファイルが処理されたこと、参照文書を特定できることを確認する。元文書に存在しない情報まで回答の正確性を保証しない。テストには既知の架空情報を含む文書を使い、回答と引用元を人が照合する。

**完了条件：AT-09、AT-12に合格する。**

### FR-06：文書処理のローカル化

文書抽出はOpen WebUI標準ローカル処理、埋め込みはOllamaのローカル埋め込みモデル、検索用保存はローカルChromaを使う。外部OCR・外部埋め込みAPI・外部検索サービスへ接続しない。Ollamaの埋め込みAPIとOpen WebUIのOllama埋め込み設定を用いる。[OL-04][OW-03]

埋め込みモデルを変更する場合は既存インデックスの互換性を仮定せず、再インデックスを必要作業として扱う。導入時に必要なモデルや依存物を取得してから通常利用へ移行する。

**完了条件：AT-09、AT-12に合格する。**

### FR-07：最小限の設定

日本語表示、デフォルトのチャットモデル、必要なシステムプロンプトを標準の設定画面で調整できること。接続先、公開範囲、保存先、クラウド無効化などの安全設定と、表示・会話の好みの設定を区別する。

管理画面で変更した永続設定が環境変数を上書きし得るため、再起動後も実際の接続先を検査する。設定変更が反映されないことを理由にDBやDATA_DIRを削除しない。[OW-03]

**完了条件：AT-06、AT-13に合格する。**

### FR-08：障害時に状態を判断できること

Ollama停止、モデル未取得、メモリ不足、ネットワーク切断の際は、標準エラー表示または運用手順で原因を切り分けられること。Ollamaが使えない場合に、外部クラウドへ自動で切り替えない。

回線切断中の返信継続や、未送信文面の全復元は保証対象外。再接続後に保存済み会話を確認し、必要に応じて再実行できること。

**完了条件：AT-14、AT-15に合格する。**

### FR-09：履歴の整理と持ち出し

標準UIで会話の削除・名前変更を行えること。会話を書き出す場合は標準エクスポートを使い、新たな出力プログラムは作らない。

会話エクスポートは、アカウント・添付ファイル・検索インデックス・設定を含むサーバー全体のバックアップの代わりにはしない。会話削除が関連ファイルや過去のバックアップもすべて消すとは扱わず、採用版の挙動を記録する。

**完了条件：AT-07、AT-18に合格する。**

### FR-10：運用の再現性

起動・停止、ログ確認、設定変更、更新前バックアップ、復元の手順を残す。インストールしたバージョンと絶対パスを記録し、毎回最新版を取り直して起動しない。

Ollamaはアプリのログイン項目と独自LaunchAgentで二重起動させない。既存Ollamaの有無を確認してから、起動元を一つに統一する。

**完了条件：AT-13、AT-16、AT-18に合格する。**

| NFR-01 | ネットワーク境界 | OllamaとOpen WebUIはIPv4 loopbackのみで待ち受ける。LAN・Tailnetへ直接APIを公開しない |
| NFR-02 | アクセス制御 | Serveの到達権限とWebUIログインを併用する。Tailnet全員が本人とはみなさない |
| NFR-03 | データ保護 | DATA_DIR・設定・ログは所有者に限定。秘密鍵を固定管理し、チャットやGitへ出さない |
| NFR-04 | ローカル処理 | 外部LLM、外部埋め込み、外部OCR、Web検索、外部ツールを利用しない |
| NFR-05 | データ保持 | 再起動・環境更新で会話、設定、添付の参照関係を失わない |
| NFR-06 | 既存環境保護 | OpenClawの接続・Sandbox動作・既存設定を変えない。共用資源の負荷は別途測定 |
| NFR-07 | 性能 | 小規模な1人利用でOOMや継続的なUI無応答を起こさない。速さは実測してモデル選定に使う |
| NFR-08 | 起動復帰 | macOSユーザーログイン後、ターミナルを開かずに利用可能。ユーザーログアウト中は非保証 |
| NFR-09 | 保守 | Open WebUIは単一インスタンス・単一worker。バージョンと依存関係を記録 |
| NFR-10 | バックアップ | 更新前・導入完了時に整合したバックアップを取り、復元試験を最低1回実施 |
| NFR-11 | 観測性 | 起動エラー・モデル接続・保存先を確認できる。本文や認証情報を不要にログ出力しない |
| NFR-12 | 最小構成 | 自作サービス、SSO、Redis、外部DB、ネットワークの作り直しを導入しない |

### 7.1 性能評価の方法

初期測定では、同じ短い日本語プロンプトと出力長上限を使い、モデル読み込み直後のコールド実行と読み込み済みのウォーム実行を分ける。UI表示時間、最初の表示可能な応答までの時間、全体の所要時間、メモリプレッシャー、OpenClaw併用時の変化を記録する。

暫定目安は、ウォーム状態で最初の応答まで30秒以内、UIの基本操作が数秒程度で反応すること。これは未測定の設計目安であり、保証値ではない。目安を外れた場合はモデル・文脈長・生成量を下げて再測定し、BOSSが日常利用できる条件を採用する。架空のtokens/secやメモリ要件は記載しない。

### 7.2 保存とバックアップの境界

主な会話データはMac miniに置くが、ブラウザには認証状態・キャッシュ・ダウンロードしたファイルが残り得る。「端末には一切データが残らない」とは説明しない。

初期バックアップは、Open WebUI停止中のDATA_DIRと設定・秘密鍵・構成記録を一組として保存する方式にする。定期頻度は週1回を初期運用案とし、実運用開始時に記録する。専用バックアップサービスの新規開発は行わない。

同じMac mini内のコピーは更新失敗への備えであって、本体故障への対策ではない。別媒体への保管先は導入時に決め、未設定なら故障時に復元できない残余リスクを明記する。クラウドへ無断でバックアップしない。

## 8. 「ローカル」と「安全」の定義

本構成におけるローカルとは、**チャット推論、文書の抽出・埋め込み、主要データの保存がMac mini上で行われること**を指す。Tailscale接続のための通信、初期パッケージ取得、モデル取得、保守時の更新までゼロになるという意味ではない。

Open WebUIのOFFLINE_MODEは外部通信全体を遮断する機構ではない。未取得の埋め込みモデルがある状態で有効化すると起動・文書処理に影響し得るため、初期準備と通常運用を分ける。[OW-03]

専用Python仮想環境は依存ライブラリの分離であり、OSレベルのSandboxではない。Open WebUI本体と依存ライブラリは実行ユーザーの権限で動く。第三者Functionsやコード実行を追加しないことは重要だが、脆弱性が存在しない保証にはならない。[OW-05]

同じホスト名の443番と9443番を使うため、別ポートであってもCookieが完全に分離されるとは考えない。ログイン・ログアウト・同時利用による干渉を試験し、同一管理者が管理する二つのサービスとして扱う。[NET-01]
